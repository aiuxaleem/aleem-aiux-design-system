The six states, and what renders them · one region: StateView
StateUse
DefaultThe component itself. One primary action per view.
LoadingSkeletonPreset in a LoadingRegion (300 ms delay, 600 ms minimum) · Spinner / Button loading for one action · ProgressBar when measurable · TypingIndicator in chat. Refetch keeps content with "Updating".
EmptyEmptyState: what belongs here + the one action that fills it. Aleem voice on conversational surfaces, neutral on admin.
ErrorField: error prop · Region: ErrorState (error, offline, timeout, not found, no access, server) + Try again · Banner over working content: Alert danger · Chat: status="failed". Say how to fix it.
PartialStateView status="partial" (content under an Alert warning) · Input warning · Select emptyMessage · an image that failed: MediaFrame says so with Try again.
SuccessToast after an action (6 s, Undo if reversible) · Alert success when it must stay · Input / Select success.
Rules that keep states kind
1
Explain, don't disableKeep submit enabled and show the field error. Disable only when the reason is visible beside the control.
2
Validate on blur, summarise on submitNever on every keystroke. On submit, focus the first invalid field; its message has role="alert".
3
Nothing silent, nothing blockingEvery wait over 300 ms shows a state; every change is announced (role=status / aria-live). Destructive actions confirm via Dialog tone="danger", never a bare "OK".
4
Never motion or colour aloneSpinners fall back to dots + label and skeletons go still under reduced motion; every tone carries a glyph and words.
5
Hold the heightSkeletons match the real layout and StateView keeps minHeight, so no state change jolts the page.
